Capítulo 5. Herencia de plantillas, modularización y archivos estáticos en Django

5.1 Introducción

En el capítulo anterior se analizó el sistema de plantillas de Django y el uso de Django Template Language (DTL) para construir interfaces dinámicas mediante variables, etiquetas, filtros, condicionales y bucles.

A medida que una aplicación incorpora nuevas páginas aparece un problema adicional: muchas interfaces comparten elementos visuales y estructurales, como la estructura HTML, encabezados, barras de navegación, pies de página, hojas de estilo y recursos gráficos.

Django proporciona mecanismos que permiten construir interfaces reutilizables mediante herencia de plantillas, bloques, inclusión de plantillas y archivos estáticos.

5.2 El problema de la repetición

Repetir la misma estructura HTML en cada página aumenta el esfuerzo de mantenimiento y puede generar inconsistencias. Si una aplicación incorpora muchas páginas, modificar una barra de navegación o un pie de página obligaría a repetir el mismo cambio en numerosos archivos.

La duplicación puede provocar:

  • mayor esfuerzo de mantenimiento;
  • inconsistencias entre páginas;
  • dificultad para realizar cambios globales;
  • aumento innecesario del código;
  • mayor posibilidad de errores.

5.3 Herencia de plantillas

La herencia de plantillas permite definir una estructura HTML general y reutilizarla desde otras plantillas. Habitualmente se crea una plantilla base denominada base.html, que contiene la estructura común de la aplicación. Las demás plantillas heredan esa estructura y definen únicamente las partes que deben cambiar.

                 base.html
                     │
       estructura común del sitio
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
   inicio.html   lista.html   detalle.html

5.4 Construcción de una plantilla base

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>
        {% block title %}
            Mi aplicación
        {% endblock %}
    </title>
</head>
<body>
    <header>
        <h1>Mi aplicación</h1>
    </header>

    <nav>
        <a href="#">Inicio</a>
        <a href="#">Productos</a>
    </nav>

    <main>
        {% block content %}
        {% endblock %}
    </main>

    <footer>
        <p>Mi aplicación web</p>
    </footer>
</body>
</html>

5.5 La etiqueta {% block %}

La etiqueta {% block nombre %}...{% endblock %} define una región que las plantillas hijas pueden reemplazar.

{% block content %}
{% endblock %}

5.6 La etiqueta {% extends %}

Una plantilla hija indica qué plantilla debe heredar mediante:

{% extends "base.html" %}

Ejemplo:

{% extends "base.html" %}

{% block title %}
    Productos
{% endblock %}

{% block content %}
    <h2>Productos disponibles</h2>
    <p>Listado de productos.</p>
{% endblock %}

5.7 Relación entre extends y block

La plantilla base define los bloques disponibles y la plantilla hija redefine los bloques que necesita personalizar. De esta manera se conserva la estructura general y cambia solamente el contenido específico.

5.8 Una plantilla base con varios bloques

{% block title %}Sistema{% endblock %}
{% block extra_css %}{% endblock %}
{% block content %}{% endblock %}
{% block extra_js %}{% endblock %}

La cantidad de bloques debe responder a necesidades reales de la interfaz. Una estructura excesivamente fragmentada puede dificultar la comprensión.

5.9 Contenido predeterminado de un bloque

Un bloque puede contener contenido predeterminado. Si una plantilla hija no lo redefine, se utiliza el contenido definido en la plantilla base.

5.10 Uso de block.super

{% block title %}
    Productos | {{ block.super }}
{% endblock %}

block.super permite recuperar el contenido definido por el bloque de la plantilla padre y ampliarlo.

5.11 Modularización mediante {% include %}

Django permite incorporar fragmentos reutilizables mediante {% include %}.

templates/
│
├── base.html
└── componentes/
    ├── navbar.html
    └── footer.html
{% include "componentes/navbar.html" %}

5.12 extends e include: responsabilidades diferentes

MecanismoPropósito
{% extends %}Heredar una estructura general.
{% block %}Definir o reemplazar regiones de esa estructura.
{% include %}Incorporar un fragmento reutilizable.

5.13 Organización modular de las plantillas

templates/
│
├── base.html
├── componentes/
│   ├── navbar.html
│   └── footer.html
└── productos/
    ├── lista.html
    └── detalle.html

5.14 Ejemplo de estructura completa

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>{% block title %}Sistema{% endblock %}</title>
</head>
<body>
    {% include "componentes/navbar.html" %}

    <main>
        {% block content %}{% endblock %}
    </main>

    {% include "componentes/footer.html" %}
</body>
</html>

5.15 Archivos estáticos

Las interfaces web suelen utilizar hojas de estilo CSS, imágenes, archivos JavaScript, íconos y otros recursos. Estos elementos se denominan archivos estáticos.

5.16 Organización del directorio static

productos/
│
├── templates/
│   └── productos/
│       ├── lista.html
│       └── detalle.html
└── static/
    └── productos/
        ├── css/
        │   └── estilos.css
        ├── js/
        │   └── aplicacion.js
        └── img/
            └── logo.png

5.17 La etiqueta {% load static %}

{% load static %}

Esta etiqueta carga la biblioteca necesaria para utilizar {% static %}.

5.18 Utilización de CSS

{% load static %}
<link rel="stylesheet"
      href="{% static 'productos/css/estilos.css' %}">

5.19 Utilización de imágenes

{% load static %}
<img src="{% static 'productos/img/logo.png' %}"
     alt="Logo">

5.20 Utilización de JavaScript

{% load static %}
<script src="{% static 'productos/js/aplicacion.js' %}"></script>

5.21 Plantillas y archivos estáticos no son equivalentes

TemplateArchivo estático
Puede contener DTL y generar HTML dinámico.Es un recurso como CSS, JavaScript o una imagen.
Es procesado por Django.Es solicitado por el navegador como recurso independiente.

5.22 Integración de base.html y archivos estáticos

{% load static %}

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>{% block title %}Sistema{% endblock %}</title>

    <link rel="stylesheet"
          href="{% static 'css/estilos.css' %}">

    {% block extra_css %}{% endblock %}
</head>
<body>

    {% include "componentes/navbar.html" %}

    <main>
        {% block content %}{% endblock %}
    </main>

    {% include "componentes/footer.html" %}

    <script src="{% static 'js/aplicacion.js' %}"></script>
    {% block extra_js %}{% endblock %}
</body>
</html>

5.23 Integración con el sistema de URLs

Una barra de navegación reutilizable debería utilizar nombres de rutas en lugar de URLs rígidas:

<nav>
    <a href="{% url 'inicio' %}">Inicio</a>
    <a href="{% url 'productos:lista' %}">Productos</a>
</nav>

5.25 Ejemplo integrador

Vista

def lista_productos(request):
    productos = [
        {"id": 1, "nombre": "Notebook"},
        {"id": 2, "nombre": "Monitor"}
    ]

    contexto = {
        "productos": productos
    }

    return render(
        request,
        "productos/lista.html",
        contexto
    )

Plantilla hija

{% extends "base.html" %}

{% block title %}
    Productos
{% endblock %}

{% block content %}
    <h1>Productos</h1>

    <ul>
        {% for producto in productos %}
            <li>
                {{ producto.nombre }}
                <a href="{% url 'productos:detalle' producto.id %}">
                    Ver detalle
                </a>
            </li>
        {% empty %}
            <li>No existen productos.</li>
        {% endfor %}
    </ul>
{% endblock %}

5.26 Diagnóstico de problemas

Caso 1: el contenido de la plantilla hija no aparece

Debe comprobarse que el nombre del bloque de la plantilla hija coincida con el definido en la plantilla base.

Caso 2: no se aplica la plantilla base

Debe revisarse la referencia utilizada en {% extends "base.html" %} y comprobar que Django pueda localizarla.

Caso 3: un componente incluido no aparece

Debe comprobarse el nombre, ubicación y ruta utilizada en {% include %}.

Caso 4: el CSS no se carga

Debe verificarse {% load static %}, la referencia creada con {% static %} y la ubicación del archivo.

Caso 5: una imagen no aparece

Debe revisarse el recorrido desde la referencia {% static %} hasta la URL generada y el archivo solicitado por el navegador.

5.27 Buenas prácticas de organización

  • Utilizar una plantilla base.
  • Evitar duplicación de estructura HTML.
  • Modularizar componentes reutilizables.
  • Mantener nombres claros para los bloques.
  • Organizar recursos estáticos en directorios comprensibles.
  • Utilizar {% static %} para recursos estáticos.
  • Utilizar {% url %} para navegación interna.
  • Mantener una jerarquía de plantillas simple y comprensible.

5.28 Aplicación al Trabajo Integrador

El Trabajo Integrador debe utilizar mecanismos de reutilización que eviten construir cada interfaz como una página completamente independiente.

Cada grupo deberá analizar qué elementos visuales son compartidos por las distintas funcionalidades y decidir cuáles corresponden a base.html, cuáles pueden modularizarse mediante {% include %} y cuáles deben definirse mediante {% block %}.

Actividad de aplicación

  1. Identificar los elementos HTML que se repiten en diferentes páginas.
  2. Crear o revisar una plantilla base.html.
  3. Definir al menos los bloques title y content.
  4. Hacer que las páginas principales hereden de la plantilla base mediante {% extends %}.
  5. Identificar al menos un componente reutilizable que pueda separarse mediante {% include %}.
  6. Revisar que la navegación utilice {% url %} en lugar de URLs rígidas.
  7. Organizar CSS, JavaScript e imágenes dentro de una estructura static.
  8. Utilizar {% load static %} y {% static %}.
  9. Verificar que los cambios de la estructura común se reflejen en las páginas hijas.
  10. Representar gráficamente la estructura de templates del proyecto.
