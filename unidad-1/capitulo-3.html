Capítulo 3. Arquitectura de Django: MVC, MVT y ciclo Request–Response

← AnteriorÍndice Unidad 1

1. Introducción

La separación de responsabilidades permite organizar aplicaciones complejas evitando concentrar datos, procesamiento, flujo y presentación en un único componente.

2. El patrón MVC

MVC distingue Model, View y Controller. Model representa datos y reglas; View la presentación; Controller coordina acciones y componentes.

3. Django y MVT

Django utiliza Model–View–Template. No conviene establecer una equivalencia estricta componente por componente entre MVC y MVT; ambos comparten principalmente la separación de responsabilidades.

4. Model en Django

Representa estructura y comportamiento relacionado con datos persistentes. El ORM vincula objetos Python con registros de una base de datos.

Tarea.objects.all()
Tarea.objects.filter(estado="pendiente")

5. View en Django

Recibe una solicitud HTTP y participa en la generación de una respuesta. Puede examinar request, recibir parámetros, consultar modelos, procesar información, preparar datos, seleccionar templates o redirigir.

6. Template

Define la presentación y puede utilizar variables, condiciones, iteraciones, filtros y etiquetas de Django Template Language.

7. URL Dispatcher

Determina qué View debe procesar una URL mediante las configuraciones de urls.py.

8. Ciclo Request–Response

Request → URL Dispatcher → View → Model / ORM → View → Template → Response

La View recibe la request, solicita datos cuando es necesario, construye el contexto, selecciona el Template y participa en la generación de la respuesta.

9. Actividad guiada y Trabajo Integrador

Reconstruir el recorrido de una funcionalidad del Trabajo Integrador, identificando URL, View, datos/modelos, contexto, Template y respuesta.

10. Evidencia de aprendizaje

El estudiante debe poder explicar las responsabilidades de cada componente y seguir el recorrido completo de una solicitud dentro de Django.

11. Preguntas para la validación oral

Las preguntas se orientan a justificar la separación de responsabilidades, diferenciar MVC y MVT, explicar Model, View, Template y URL Dispatcher, y reconstruir el ciclo Request–Response a partir del proyecto desarrollado.

12. Síntesis

La arquitectura MVT organiza responsabilidades y el ciclo Request–Response permite comprender cómo colaboran los componentes de Django para transformar una solicitud HTTP en una respuesta.
