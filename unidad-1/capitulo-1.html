Capítulo 1. De la Web a las aplicaciones Web: arquitectura cliente-servidor, HTTP y frameworks

1. Introducción

Programación Web II avanza desde los conocimientos de frontend adquiridos en Programación Web I hacia la construcción de aplicaciones web completas, incorporando procesamiento del lado del servidor, persistencia de datos y herramientas para organizar aplicaciones de mayor complejidad.

2. De una página web a una aplicación web

Una página web es un documento interpretado por un navegador; un sitio web reúne páginas y recursos relacionados; una aplicación web incorpora además procesamiento, gestión de información, reglas y generación dinámica de resultados.

3. Contenido estático y dinámico

Los recursos estáticos pueden entregarse esencialmente sin modificación para cada solicitud. El contenido dinámico se genera según datos, usuario, permisos y operación solicitada.

4. Arquitectura cliente-servidor

El cliente inicia solicitudes; el servidor las recibe, procesa y genera respuestas. En la Web, el navegador suele actuar como cliente.

5. Solicitud de una página

Usuario → Navegador → HTTP Request → Servidor / Aplicación → Procesamiento → Datos / reglas → HTTP Response → Navegador → Usuario

6. HTTP

HTTP es el protocolo de intercambio de información entre clientes y servidores basado en solicitud y respuesta.

7. HTTP Request

Puede contener método HTTP, URL o ruta, encabezados, parámetros y eventualmente un cuerpo.

GET /productos/15/ HTTP/1.1
Host: ejemplo.com

8. Métodos HTTP

GET consulta información; POST envía información o crea recursos; PUT reemplaza o actualiza; PATCH modifica parcialmente; DELETE elimina.

9. HTTP Response y códigos de estado

Una respuesta incluye código de estado, encabezados y, cuando corresponde, un cuerpo. Entre los códigos relevantes se encuentran 200, 201, 301/302, 400, 401, 403, 404 y 500.

10. Frontend y backend

El frontend se ocupa de estructura, presentación e interacción en el navegador. El backend recibe solicitudes, aplica reglas, valida, autentica, controla permisos, accede a datos y genera respuestas.

11. Persistencia

La base de datos permite conservar información más allá de una solicitud particular.

12. ¿Por qué utilizar frameworks?

Los frameworks proporcionan estructura, componentes, convenciones y herramientas reutilizables para resolver problemas frecuentes del desarrollo web.

13. Django

Django proporciona componentes para URLs, Views, Models y ORM, Templates, Forms, Authentication, Permissions y administración.

14. Aplicación al Trabajo Integrador

Analizar conceptualmente una funcionalidad del proyecto identificando cliente, solicitud, procesamiento, datos necesarios, decisiones del servidor y respuesta.
