Capítulo 2. Introducción al Framework DJANGO

En el documento anterior analizamos cómo funciona una aplicación web desde una perspectiva general. Identificamos la participación de un cliente, generalmente representado por el navegador, y de un servidor, encargado de recibir solicitudes, procesarlas y generar respuestas.

También observamos que, a medida que una aplicación aumenta su complejidad, aparecen problemas que se repiten en diferentes proyectos: gestionar URLs, acceder a bases de datos, validar información, autenticar usuarios, controlar permisos, generar contenido dinámico y organizar el código.

Los frameworks web proporcionan estructuras y herramientas destinadas a resolver de manera organizada muchas de estas necesidades.

Durante Programación Web II utilizaremos Django, un framework de desarrollo web basado en Python que nos permitirá avanzar progresivamente desde la arquitectura conceptual estudiada hasta la implementación de una aplicación web completa.

2. ¿Qué es Django?

Django es un framework de desarrollo web de alto nivel escrito en Python.

Su propósito es facilitar la construcción de aplicaciones web proporcionando componentes, convenciones y herramientas reutilizables para resolver problemas comunes del desarrollo.

Esto significa que Django no reemplaza al lenguaje Python ni construye automáticamente nuestra aplicación. En cambio, proporciona una estructura sobre la cual podemos organizar nuestro código y desarrollar las funcionalidades específicas de nuestro proyecto.

Por ejemplo, Django incorpora mecanismos para:

  • recibir y procesar solicitudes HTTP;
  • asociar URLs con funcionalidades;
  • trabajar con bases de datos;
  • generar contenido HTML dinámicamente;
  • validar formularios;
  • autenticar usuarios;
  • gestionar permisos;
  • administrar información;
  • aplicar mecanismos de seguridad;
  • realizar pruebas.

3. Breve historia de Django

El origen de Django se remonta a comienzos de la década de 2000, cuando un equipo de desarrollo del periódico Lawrence Journal-World, en Kansas, necesitaba construir y mantener varias aplicaciones web en tiempos reducidos.

En lugar de desarrollar desde cero soluciones similares para cada proyecto, comenzaron a reutilizar componentes de software que resolvían problemas recurrentes.

Entre 2003 y 2005, desarrolladores como Adrian Holovaty y Simon Willison fueron consolidando esas herramientas hasta convertirlas en un framework.

En julio de 2005, Django fue publicado como proyecto de código abierto.

Posteriormente se creó la Django Software Foundation, organización que acompaña el desarrollo y mantenimiento del framework.

Desde entonces Django ha evolucionado de manera continua, incorporando mejoras
relacionadas con:

  • acceso a bases de datos;
  • seguridad;
  • autenticación;
  • administración;
  • soporte para aplicaciones síncronas y asíncronas;
  • compatibilidad con nuevas versiones de Python.

Para esta asignatura, la historia de Django nos interesa principalmente porque permite
comprender una idea central:

Django surgió a partir de la necesidad de reutilizar soluciones y evitar reconstruir constantemente los mismos componentes.

Esta filosofía está directamente relacionada con uno de sus principios más conocidos: DRY – Don’t Repeat Yourself.

4. ¿Por qué utilizar un framework?

Supongamos que necesitamos desarrollar una aplicación para gestionar inscripciones de estudiantes.

  • interpretar una URL;
  • decidir qué función ejecutar;
  • conectarnos con una base de datos;
  • obtener registros;
  • generar HTML;
  • procesar formularios;
  • iniciar y mantener sesiones;
  • almacenar contraseñas de forma segura;
  • controlar permisos;
  • prevenir determinadas vulnerabilidades.

Muchas de estas necesidades no son particulares de nuestra aplicación.

Por ello, resulta conveniente utilizar componentes ya probados y organizados dentro de una arquitectura común.

Django permite que el desarrollador concentre una mayor parte de su trabajo en:

los requerimientos, las reglas del dominio y las funcionalidades particulares de la aplicación.

5. Principales características de Django

5.1 Desarrollo rápido

Django proporciona una estructura inicial y numerosos componentes integrados que reducen la necesidad de desarrollar soluciones repetitivas.

Esto permite pasar con mayor rapidez desde la definición de una necesidad hasta la construcción de una funcionalidad.

Sin embargo, desarrollo rápido no significa desarrollo improvisado. La organización de la aplicación, el diseño del modelo de datos y las decisiones técnicas continúan siendo fundamentales.

5.2 Principio DRY

Uno de los principios promovidos por Django es:

DRY – Don’t Repeat Yourself

La idea consiste en evitar la duplicación innecesaria de conocimiento y código.

Django promueve la reutilización y centralización de responsabilidades.

Este principio aparecerá durante toda la asignatura mediante:

  • reutilización de templates;
  • herencia;
  • modelos centralizados;
  • formularios;
  • componentes reutilizables;
  • organización modular.

6. Django como framework “batteries included”

Django suele describirse como un framework de tipo “batteries included”.

Esta expresión significa que incorpora de manera predeterminada una amplia cantidad de herramientas necesarias para el desarrollo de aplicaciones web.

Entre ellas encontramos:

Necesidad Herramienta o componente

Gestión de URLs URL Dispatcher

Procesamiento de solicitudes Views

Persistencia de datos Models + ORM

Generación de HTML Templates

Procesamiento de formularios Forms

Gestión de usuarios Authentication

Control de acceso Permissions

Administración Django Admin

Seguridad Mecanismos integrados

Pruebas Testing framework

Esto no significa que Django resuelva automáticamente todas las decisiones del proyecto, sino que proporciona puntos de partida y componentes reutilizables.

Una de las características centrales de Django es su ORM – Object Relational Mapper.

El ORM permite interactuar con una base de datos utilizando objetos y código Python, reduciendo la necesidad de escribir directamente consultas SQL para muchas operaciones habituales.

Por ejemplo, conceptualmente podríamos expresar:

Producto.objects.all()

para recuperar todos los productos almacenados.

O:

Producto.objects.filter(activo=True)

para obtener solamente los productos activos.

Más adelante estudiaremos cómo definir modelos, crear relaciones entre ellos y realizar operaciones de consulta, creación, modificación y eliminación.

Por ahora interesa comprender que:

los modelos de Django constituyen un puente entre el código Python y la base de datos.

8. Sistema de administración

Django incorpora una interfaz denominada Django Admin.

Esta herramienta permite generar rápidamente una interfaz de administración para los modelos definidos en la aplicación.

Desde ella es posible, según la configuración realizada:

  • consultar registros;
  • crear información;
  • modificar datos;
  • eliminar registros;
  • realizar búsquedas;
  • aplicar filtros.

No debe confundirse, sin embargo, con la interfaz final destinada a los usuarios de la aplicación.

9. Autenticación y autorización

Otra característica importante es que Django incorpora mecanismos para gestionar:

Autenticación

Permite determinar:

¿Quién es el usuario?

Incluye herramientas para:

  • usuarios;
  • contraseñas;
  • inicio de sesión;
  • cierre de sesión;
  • sesiones.

Autorización

Permite determinar:

¿Qué puede hacer ese usuario?

Django proporciona mecanismos basados en:

  • permisos;
  • grupos;
  • restricciones de acceso.

Estos conceptos serán abordados con mayor profundidad en la Unidad 5.

10. Seguridad

Django incorpora mecanismos destinados a reducir riesgos frecuentes del desarrollo web.

Entre ellos encontramos protección frente a problemas como:

  • Cross-Site Request Forgery (CSRF);

templates; ● inyección SQL, especialmente mediante el uso del ORM; ● manejo inseguro de contraseñas; ● determinadas formas de manipulación de solicitudes.

Sin embargo, utilizar Django no garantiza automáticamente que una aplicación sea segura.

La seguridad también depende de:

  • las decisiones del desarrollador;
  • la configuración;
  • la validación de entradas;
  • la gestión de permisos;
  • el almacenamiento de secretos;
  • el despliegue;
  • el mantenimiento de dependencias.

11. Modularidad

Django favorece la organización modular.

Una aplicación compleja puede dividirse en componentes que atienden diferentes responsabilidades.

Por ejemplo, un sistema académico podría contar con módulos destinados a:

Sistema académico
│
├── usuarios
├── estudiantes
├── asignaturas
├── inscripciones
└── calificaciones

En Django, esta idea se implementa mediante aplicaciones.

Aquí aparece una distinción fundamental:

Un proyecto Django puede contener múltiples aplicaciones Django.

Esta diferencia es muy importante para comenzar a trabajar con el framework.

Proyecto

Un proyecto Django representa la configuración global de una solución web.

Incluye, entre otras cosas:

  • configuración general;
  • aplicaciones instaladas;
  • base de datos;
  • middleware;
  • rutas principales;
  • parámetros de despliegue.

Podemos imaginarlo como el contenedor general de la solución.

Aplicación

Una aplicación Django representa un módulo que reúne funcionalidades relacionadas.

Por ejemplo:

proyecto_academico/
│
├── usuarios/
├── estudiantes/
├── asignaturas/
└── inscripciones/

Cada aplicación puede contener:

  • modelos;
  • vistas;
  • rutas;
  • formularios;
  • templates;
  • pruebas.

Una aplicación Django puede diseñarse de manera suficientemente modular como para ser reutilizada en distintos proyectos.

Podemos representar esta relación de la siguiente manera:

PROYECTO DJANGO

El proyecto administra la configuración general.

Cada aplicación concentra funcionalidades relacionadas con un dominio o responsabilidad particular.

Esta organización favorece:

  • modularidad;
  • mantenibilidad;
  • reutilización;
  • separación de responsabilidades.

14. Creación de un proyecto Django

Cuando ejecutamos:

django-admin startproject mi_proyecto

Django genera automáticamente una estructura inicial.

Por ejemplo:

mi_proyecto/
│
├── manage.py
│
└── mi_proyecto/
├── __init__.py
├── settings.py
├── urls.py
├── asgi.py
└── wsgi.py

Esta estructura contiene la configuración básica necesaria para comenzar.

15. Principales archivos de un proyecto

manage.py

Es una herramienta que permite ejecutar comandos relacionados con el proyecto.

Por ejemplo:

python manage.py runserver
python manage.py migrate
python manage.py startapp productos
Durante la asignatura utilizaremos manage.py permanentemente.
settings.py

Contiene gran parte de la configuración general del proyecto.

Allí se definen, entre otros elementos:

  • aplicaciones instaladas;
  • base de datos;
  • middleware;
  • configuración de templates;
  • idioma;
  • zona horaria;
  • archivos estáticos.

No estudiaremos todas estas opciones inmediatamente. Las iremos incorporando a medida que sean necesarias.

urls.py

Permite establecer el sistema principal de rutas de la aplicación.

Conceptualmente responde a una pregunta:

Cuando llega una determinada URL, ¿qué componente debe atenderla?

asgi.py y wsgi.py

Son archivos utilizados para comunicar la aplicación Django con servidores y entornos de ejecución.

En esta primera etapa no necesitaremos modificarlos.

Su importancia será retomada cuando trabajemos sobre despliegue y producción.

16. Creación de una aplicación Django

Dentro de un proyecto podemos crear una aplicación mediante:

python manage.py startapp productos

Django generará una estructura similar a:

productos/
│
├── migrations/
├── __init__.py
├── admin.py
├── apps.py
├── models.py
├── tests.py
└── views.py

Cada archivo tiene una responsabilidad particular.

17. Algunos componentes de una aplicación

models.py

Contiene las clases que representan información persistente.

Ejemplo:

class Producto(models.Model):
nombre = models.CharField(max_length=100)
precio = models.DecimalField(max_digits=10, decimal_places=2)
views.py

Contiene funciones o clases que procesan solicitudes y generan respuestas.

Por ejemplo:

def listado_productos(request):
...
admin.py

Permite configurar la integración de los modelos con Django Admin.

tests.py

Permite definir pruebas automatizadas.

migrations/

Contiene los archivos que permiten registrar y aplicar cambios en la estructura de la base de datos.

19. Preparación del entorno de desarrollo

Para trabajar con Django es recomendable utilizar un entorno virtual de Python.

Un entorno virtual permite mantener aisladas las dependencias de un proyecto.

Por ejemplo:

Proyecto A Python + Django versión X Proyecto B Python + Django versión Y

Ambos proyectos pueden coexistir en una misma computadora sin necesidad de compartir exactamente las mismas dependencias.

20. Creación de un entorno virtual

Python incorpora el módulo venv.

Para crear un entorno virtual podemos ejecutar:

python3 -m venv venv

Windows

python -m venv venv
El segundo venv representa el nombre de la carpeta donde se almacenará el entorno.

21. Activación del entorno virtual

Linux / macOS

source venv/bin/activate

Windows

venv\Scripts\activate

Cuando el entorno se encuentra activo, los paquetes instalados mediante pip quedan asociados a ese entorno.

22. Instalación de Django

Con el entorno virtual activo podemos instalar Django mediante:

python -m pip install Django

Posteriormente podemos verificar la instalación:

python -m django --version

Para el desarrollo de la asignatura se establecerá una versión común de Python y Django, de manera que todos los grupos trabajen sobre un entorno tecnológico equivalente.

24. El servidor de desarrollo

El comando:

python manage.py runserver

inicia un servidor incluido con Django destinado al desarrollo y pruebas locales.

Es importante comprender que este servidor:

no está diseñado para ser utilizado directamente como servidor de producción.

En la Unidad 6 estudiaremos la diferencia entre los entornos de desarrollo y producción y analizaremos tecnologías utilizadas para desplegar aplicaciones Django.

25. Gestión de dependencias

Los paquetes instalados dentro de un entorno pueden registrarse en un archivo.

Por ejemplo:

pip freeze > requirements.txt

El archivo podría contener:

Django==X.Y.Z ...

Posteriormente, otro integrante del equipo puede reconstruir el entorno mediante:

pip install -r requirements.txt

Esto resulta especialmente importante en el desarrollo colaborativo porque ayuda a garantizar que todos los integrantes trabajen con dependencias compatibles.

Django es un framework de desarrollo web basado en Python que proporciona una estructura organizada para construir aplicaciones.

Entre sus principales características encontramos:

  • organización modular;
  • URL routing;
  • ORM;

Aplicación Django: módulo que concentra un conjunto relacionado de funcionalidades.
