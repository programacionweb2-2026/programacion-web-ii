Pasos recomendados para iniciar un proyecto Django

Guía práctica para crear el entorno virtual, iniciar el proyecto, incorporar una aplicación y comprobar el circuito URL → vista → plantilla → respuesta.

← Volver al índice de la Unidad 2

Propósito de la guía

Entorno virtualAislar Django y las dependencias del proyecto.
ProyectoCrear la configuración general del sitio web.
AplicaciónImplementar una funcionalidad concreta y conectarla al proyecto.
Idea clave El entorno virtual, el proyecto y la aplicación son elementos diferentes. Habitualmente se crea un entorno y un proyecto, mientras que dentro del proyecto pueden existir varias aplicaciones.

Antes de comenzar

Abra una terminal y verifique que Python se encuentre instalado:

python3 --version

En algunas instalaciones puede utilizarse una versión específica, por ejemplo:

python3.12 --version
Convención de esta guía Se utilizará mi_proyecto como carpeta de trabajo, config para la configuración general y cursos como aplicación de ejemplo. Estos nombres pueden adaptarse al Trabajo Final Integrador.

A. Preparar la carpeta y el entorno virtual

1Crear la carpeta de trabajo

mkdir mi_proyecto
cd mi_proyecto

Todos los archivos del proyecto quedarán contenidos en esta carpeta.

2Crear el entorno virtual

En Linux:

python3 -m venv .venv

Si se trabaja específicamente con Python 3.12:

python3.12 -m venv .venv
¿Por qué .venv?Es un nombre convencional y permite que editores como Visual Studio Code detecten el entorno con facilidad.

3Activar el entorno virtual

Linux o macOS:

source .venv/bin/activate

Windows (PowerShell):

.venv\Scripts\Activate.ps1
ComprobaciónAl activarse correctamente, la terminal suele mostrar (.venv) antes del indicador de comandos.

4Actualizar pip e instalar Django

python -m pip install --upgrade pip
python -m pip install django

Comprobar la versión instalada:

python -m django --version
↑ Volver al inicio

B. Crear y comprobar el proyecto Django

5Crear el proyecto

django-admin startproject config .
El punto final es importanteIndica que Django debe crear el proyecto en la carpeta actual y evita una carpeta adicional innecesaria.

La estructura inicial será semejante a la siguiente:

mi_proyecto/
├── .venv/
├── config/
│   ├── __init__.py
│   ├── asgi.py
│   ├── settings.py
│   ├── urls.py
│   └── wsgi.py
└── manage.py

6Aplicar las migraciones iniciales

python manage.py migrate

Este comando prepara las tablas requeridas por las aplicaciones incorporadas por Django.

7Iniciar el servidor de desarrollo

python manage.py runserver

Ingresar desde el navegador a http://127.0.0.1:8000/.

Resultado esperadoSi aparece la página de bienvenida de Django, el proyecto fue creado correctamente. Para detener el servidor, presione Ctrl + C.
↑ Volver al inicio

C. Crear e integrar una aplicación

8Crear la aplicación

python manage.py startapp cursos

Se incorporará una carpeta con archivos para los modelos, las vistas, la administración, las pruebas y las migraciones de esta funcionalidad.

9Registrar la aplicación

En config/settings.py, agregar la clase de configuración en INSTALLED_APPS:

INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "cursos.apps.CursosConfig",
]

10Crear las rutas de la aplicación

Crear manualmente el archivo cursos/urls.py:

from django.urls import path
from . import views

app_name = "cursos"

urlpatterns = [
    path("", views.inicio, name="inicio"),
]

11Crear la vista

En cursos/views.py:

from django.shortcuts import render


def inicio(request):
    contexto = {
        "titulo": "Listado de cursos",
    }
    return render(request, "cursos/inicio.html", contexto)

12Conectar las rutas con el proyecto

Modificar config/urls.py:

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("cursos/", include("cursos.urls")),
]

13Crear la plantilla

Crear la estructura de carpetas:

cursos/
└── templates/
    └── cursos/
        └── inicio.html

Agregar en inicio.html:

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{{ titulo }}</title>
</head>
<body>
    <h1>{{ titulo }}</h1>
    <p>Esta página fue generada con una plantilla de Django.</p>
</body>
</html>
↑ Volver al inicio

D. Probar el circuito completo

14Ejecutar y acceder a la aplicación

python manage.py runserver

Ingresar a http://127.0.0.1:8000/cursos/.

URL solicitada→URLs del proyecto→URLs de la aplicación→Vista y contexto→Plantilla HTML→Respuesta
Resultado esperadoEl navegador debe mostrar el título “Listado de cursos”, enviado por la vista dentro del diccionario de contexto y representado en la plantilla mediante {{ titulo }}.
↑ Volver al inicio

E. Registrar las dependencias

15Generar requirements.txt

python -m pip freeze > requirements.txt

Otra persona podrá reconstruir el entorno con:

python -m pip install -r requirements.txt
No guardar el entorno virtual en GitConviene incluir .venv/ en el archivo .gitignore. Las dependencias necesarias quedan documentadas en requirements.txt.

Qué hacer en cada nueva sesión de trabajo

No se vuelve a crear el entorno, el proyecto ni la aplicación. En Linux, normalmente solo se ejecuta:

cd mi_proyecto
source .venv/bin/activate
python manage.py runserver

Al finalizar el trabajo:

deactivate
Acción¿Cuándo se realiza?
Crear .venvUna vez, al preparar el proyecto.
Activar .venvCada vez que se abre una nueva terminal de trabajo.
Crear el proyectoUna vez.
Crear aplicacionesCuando el sistema requiere un nuevo módulo funcional.
Ejecutar runserverCada vez que se necesita probar el sitio localmente.

Problemas frecuentes

SituaciónQué revisar
No module named djangoConfirmar que el entorno virtual esté activado y que Django se haya instalado dentro de él.
TemplateDoesNotExistRevisar la ruta cursos/templates/cursos/inicio.html, el nombre indicado en render() y el registro de la aplicación.
Error 404Verificar la URL escrita en el navegador y la conexión entre config/urls.py y cursos/urls.py.
El puerto está ocupadoDetener el servidor anterior o ejecutar python manage.py runserver 8001.
La terminal no muestra (.venv)Activar nuevamente el entorno antes de instalar dependencias o ejecutar Django.
Práctica recomendadaLeer el mensaje de error completo y localizar el último archivo propio mencionado. Django suele indicar el archivo, la línea y el tipo de problema.
